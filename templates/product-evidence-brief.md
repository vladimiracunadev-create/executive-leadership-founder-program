# Product Evidence Brief

> Entregable de las clases de producto, innovación y validación.
> Sirve para decidir **si construir**, no para documentar lo ya construido.

## 1. Hipótesis

Escrita como afirmación refutable:

> Creemos que **[segmento]** con **[problema]** hará **[comportamiento observable]**
> si le damos **[solución]**, y lo sabremos porque veremos **[métrica]** alcanzar
> **[umbral]** en **[plazo]**.

Si no se puede escribir así, todavía no es una hipótesis: es una intención.

## 2. Qué tipo de riesgo se está probando

| Riesgo | ¿Es el que bloquea ahora? | Cómo se prueba |
|---|---|---|
| Deseabilidad — ¿alguien lo quiere? | | |
| Viabilidad — ¿el negocio se sostiene? | | |
| Factibilidad — ¿podemos construirlo? | | |
| Usabilidad — ¿saben usarlo? | | |

Se prueba **un riesgo por experimento**. Probar todos a la vez no distingue cuál falló.

## 3. Experimento

- **Diseño:** qué se hace exactamente y con quién.
- **Tamaño y duración:** cuántos casos y cuánto tiempo, decidido **antes**.
- **Criterio de éxito:** el umbral, fijado antes de mirar el dato.
- **Criterio de fracaso:** el umbral por debajo del cual se abandona.
- **Coste del experimento:** en horas y en dinero.

## 5. Qué aprendimos

Tres partes, separadas a propósito:

- **Lo que el dato dice:** solo lo observado.
- **Lo que interpretamos:** la explicación, marcada como interpretación.
- **Lo que sigue sin saberse:** la incógnita que este experimento no tocó.

## 6. Amenazas a la validez

- ¿La muestra representa al segmento o son los usuarios más entusiastas?
- ¿Se midió comportamiento o declaración de intención?
- ¿Hubo algún cambio externo en el periodo que explique el resultado?
